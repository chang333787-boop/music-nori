## 1. 두드림 지연(`#/calib`)

**하는 일**: 딸깍 소리에 맞춰 8번 두드려, 이 기기에서 '소리가 들린 때'와 '두드림이 들어온 때' 사이의 시간을 잰다. 잰 값은 모든 박 판정에서 뺀다(`engine/judge.js` `judgeTaps`의 `latency`). 1~2학년 기기는 선생님이 대신 잰다.

**흐름(한 화면에 할 일 하나)**: ① 설명 → ② 두드리기 → ③ 결과.
- 준비 딸깍 4번(센박 소리 · 높은 딸깍) → 딸깍 8번(90 BPM · 0.667초 간격). 화면 아무 곳이나 두드리거나 스페이스.
- 재는 8번 동안은 박에 맞춰 바뀌는 그림을 두지 않는다(눈이 아니라 귀로 맞추게). 두드릴 때마다 큰 면이 턱까지 눌리고 점이 하나씩 찬다.
- 잰 값이 있으면 화면을 열 때 ③ 결과로 바로 간다. 판정 너그러움 · 기록 한 줄 복사는 결과 단계에 있다(기술 값은 접힌 '자세히').

**시계 맞추기**: 딸깍은 오디오 시계(`AudioContext.currentTime`)로 예약한다. 두드림은 `pointerdown`·`keydown`의 `event.timeStamp`(performance.now 기준 ms)를 그대로 쓴다. 둘을 같은 시계로 놓는 일은 `app/js/clock.js`의 `audioToPerf`(박 놀이 `tap.js`와 같은 길).
- `outputTimestamp`: `ctx.getOutputTimestamp()`의 `{contextTime, performanceTime}` 짝으로 바꾼다. 스피커로 나가는 때라 출력 지연이 들어 있다.
- `latencyGuess`: 위가 없으면(옛 사파리 등) `performance.now() + (t − currentTime + outputLatency 또는 baseLatency)`로 어림한다.
- 재는 9초 동안 40ms마다 바꾸기 값을 받아 **가운데 값**을 쓴다. 소리 길을 막 연 뒤 잠깐은 `getOutputTimestamp`가 0을 줘서 어림으로 바뀌므로, 두 방법의 값을 따로 모아 섞지 않는다(오디오 출력 시각 표본이 셋 이상이면 그것만). 이 맥의 헤드리스 크로미움에서 재 보니 `outputTimestamp` 바꾸기 값은 6초 동안 ±0.1ms로 고르고, 어림 값은 그보다 7ms쯤 일렀다(첫 순간에는 outputLatency가 아직 0이라 25ms쯤 어긋날 수 있음).

**값 정하기**(`engine/judge.js` `estimateLatency`): 두드림마다 가장 가까운 딸깍과의 차이 → 가운데 값. 가운데에서 120ms 넘게 벗어난 두드림은 버리고 다시 계산. 5개 미만이 남거나 흔들림(가운데 절대 편차)이 40ms를 넘으면 '다시 해 볼까요?'. 준비 소리 때 두드린 것은 재는 구간(첫 딸깍 − 반 박 ~ 끝 딸깍 + 반 박) 밖이라 빠진다.

**기록 한 줄**(결과 → 자세히 → '기록 한 줄 복사'): 0단계 관문 '기기별 두드림→소리 지연 기록'에 이 줄을 붙인다. 클립보드가 막히면 글 상자에 보여 준다.
```
날짜 · OS · 화면 · 표본율 · baseLatency · outputLatency · 두드림 지연 ms ± 흔들림(개수) · 방법
2026-11-07 · 맥 · 화면 1366×768 · 48000Hz · baseLatency 5ms · outputLatency 27ms · 두드림 지연 35ms ± 7ms(8개) · outputTimestamp
```
(위 예는 자동 시험의 가짜 두드림 값이다 — 사람이 잰 값이 아님.)

**자동으로 확인한 것 · 못 한 것**
- 확인함: 들린 시각 + 35ms(±8ms 흔들어)에 가짜 `pointerdown`을 넣으면 34~35ms · 흔들림 5~7ms · 8개로 나온다 → 시계 바꾸기와 값 정하기가 맞다. 준비 소리 때 넣은 두드림은 빠진다.
- 못 함: **사람의 두드림 지연**(손 · 터치 화면 · 입력 지연 · 사람이 조금 앞서 두드리는 버릇)은 사람이 두드려야만 잴 수 있다. 아래 표의 '두드림 지연' 칸은 선생님이 그 기기에서 `#/calib`를 하고 기록 한 줄을 붙여 채운다.

## 2. 스피커 크기(`#/speaker` · `app/js/eq.js`)

**하는 일**: 음높이마다 소리 크기 배수를 정한다. 기준 = 라4(A4 · 69) = 1. 점 다섯 도4 · 솔4 · 높은 도 · 높은 솔 · 아주 높은 도(60 · 67 · 72 · 79 · 84) + 참고 낮은 도(48 · 손대지 않으면 저장하지 않음). 저장하면 `eq.js`가 모든 음(`Engine.note`)의 세기에 곱한다.

**귀로 맞추기(기본)**: ① 설명 → ② 맞추기 → ③ 결과(저장). 기준 소리와 맞출 소리를 번갈아(기준 → 0.8초 → 맞출 소리 → 1.25초 → …) 들려주고, 밀대(−6dB ~ +6dB = 배수 0.5 ~ 2)로 같은 크기가 되게 맞춘다. 악기는 피아노 또는 실로폰. 맞추는 동안은 저장된 맞춤을 끈다(옛 값이 또 곱해지지 않게) · 화면을 떠나면 다시 켠다. 결과 단계에 음높이별 기둥(가운데 줄 = 그대로)과 '고친 대로 들어 보기'.

**마이크로 재기(선생님 기기 · 고르면)**: 같은 음들(라4 + 점 여섯)을 두 바퀴 틀고, 음마다 `마이크 크기 ÷ 보낸 크기(디지털)`를 잰 뒤 라4와 견준 비율의 제곱근을 배수로 제안한다. 처음 0.8초 조용할 때 잰 잡음 크기를 뺀다. 압축기 · 울림을 거치지 않는 길로 틀어 재는 값이 흔들리지 않게 했다. `getUserMedia({ echoCancellation:false, noiseSuppression:false, autoGainControl:false })` — 반향 지우기가 켜져 있으면 우리 소리를 지워 버린다. 소리는 기기 안에서 크기만 재고 녹음 · 저장 · 전송하지 않는다(화면에도 적음). 마이크도 낮은 소리를 다르게 들을 수 있어 제안값은 귀로 한 번 더 들어 보고 저장한다. 허락 대답이 10초 안에 없으면 '귀로 맞춰 주세요'.
- 자동 확인 못 함: 헤드리스 크로미움(가짜 마이크 장치 · 허락 미리 줌)에서도 `getUserMedia`가 대답하지 않아, 마이크 재기 계산은 실제 기기에서만 확인할 수 있다. 대답이 없을 때 10초 뒤 안내가 뜨는 것까지는 확인했다.

**`eq.js`**: `pitchGain(p)` = 저장된 점들 사이를 음 번호로 직선 보간 · 끝 밖은 끝 값 · 없으면 1 · 0.5~2로 자름. 저장한 표는 읽어 두고(소리마다 저장소를 읽지 않음) 저장 · 초기화 · 다른 탭에서 바뀔 때 다시 읽는다. **`import './eq.js'`만 해도** `engine.pitchGain`이 붙는다(부작용 import) → `audio.js` `Engine.note`의 한 줄 고리 `vel *= this.pitchGain ? this.pitchGain(p) : 1`. 지금은 `speaker.js`만 import하므로, 앱 전체에 늘 적용하려면 `main.js`에서 `import './eq.js'` 한 줄이 필요하다.

## 3. 합성음 높이 시험(`node tests/pitch.test.cjs`)

**재는 것**: `audio.js`의 악기 23가지(piano xylo marimba recorder gayageum bass pad violin strings cello contrabass pizz flute clarinet oboe trumpet horn tuba harp celesta glock choir timpani)를 각자 쓸 만한 음역에서 5~6음씩, 표본율 48000Hz · 44100Hz 두 가지로 OfflineAudioContext에 그려 기본 주파수를 재고 `freq(p)`와 센트 차이를 본다. 관문 |센트| ≤ 6.

**재는 법**(시간 영역 · YIN 계열)
1. 직류 걸러 내기(한 극 고역 통과 · 약 8Hz) — 뜯는 소리(KS)는 처음 잡음의 평균이 직류로 오래 남는다. 시간에 따라 바뀌지 않는 거름이라 음 높이는 그대로.
2. 소리가 살아 있는 구간만(5ms 토막 크기가 가장 큰 토막의 −30dB 아래로 내려가기 전).
3. 거친 주기 — 세 곳에서 평균을 뺀 상관 계수를 기대 주기의 0.45~2.2배에서 구해, 가장 높은 봉우리의 97%를 넘는 첫 봉우리(McLeod 방식). 한 옥타브 틀린 소리도 잡히게 넓게 본다.
4. 다듬기 — 토막마다 주기 1개 → 2개 → 4개 … 약 20ms까지 늘려 가며 상관 계수 봉우리를 포물선으로 다듬고 주기 = τ/m. 주기 여러 개를 건너 재면 표본 하나의 오차가 m으로 나뉜다. 앞 단계 주기로 다음 자리를 예측하니 어긋난 배음(글로켄 · 팀파니)에도 이웃 봉우리로 튀지 않는다.
5. 토막마다 센트를 내고 평균. 떨림이 있는 악기는 떨림이 여러 번 들어가는 1.55초(0.35~1.9초)를 평균한다(떨림이 반 번 남아도 1센트 아래). 가야금은 농현(0.35초~) 앞 0.04~0.33초. 표의 '잰 구간' 칸에 적힌다.
6. **자가 점검** — 일부러 +3 · −4.5 · −2 · +5 · +2.5 · −3센트 어긋나게 그린 사인 · 톱니 · 네모를 0.3센트 안으로 돌려줘야 표를 믿는다. 이 맥: 최대 오차 0.06센트.

**결과(2026-11-07 · 이 맥 · 크로미움 헤드리스 · 272음 · 약 10초 · 세 번 돌려 같음)**

| 악기 | 가장 큰 차이 | 까닭 |
|---|---|---|
| **가야금** | **−15.3센트**(솔4 · 44100Hz) · −14.4(높은 도 · 48000Hz) — 관문 넘음 5음 | **합성 방식.** Karplus-Strong 줄 길이 N = round(sr/f) 표본 + 두 점 평균이 반 표본을 더 늦춰 실제 주기가 N + 0.5 → 늘 0~1표본 낮다. 잰 값이 예상(−1200·log2((round(sr/f)+0.5)·f/sr))과 0.1센트까지 같다. 표본율 따라 음마다 달라짐. |
| 피아노 | +3.9 | 배음을 일부러 늘림(k배음 × (1 + 0.0004k²)) — 기본음 자체는 +0.7센트, 늘어난 배음이 주기를 조금 끌어올림 |
| 합창 · 패드 | +3.6 | 일부러 어긋낸 소리(합창 +7센트 하나 · 패드 ×1.005 하나)의 평균 |
| 호른 | +1.2 | +4센트 어긋낸 둘째 소리 |
| 피치카토 | −2.0 | 처음 0.12초 동안 내려가는 필터(위상이 바뀌며 아주 조금 낮게) |
| 나머지 열여섯 | 1센트 안 | — |

**고칠 곳(보고만 · `audio.js`는 고치지 않음)**: 가야금 `_ksBuffer`를 하프 · 피치카토의 `_pluckBuf`처럼 바꾸면 된다 — N = round(sr/f − 0.5)로 잡고 `playbackRate = f·(N+0.5)/sr`로 맞추거나, 분수 지연(올패스)을 넣는다.
**같이 본 것**: 하프 높은 음(도7)은 KS 두 점 평균이 한 주기마다 기본음을 4.5%씩 깎아(22050Hz 버퍼 · 주기 10.5표본) 30ms쯤이면 사라지고 직류만 남는다 — 음 높이는 맞지만(−0.2센트) '딱' 소리처럼 짧다.

## 5. 판정 창 숫자 출처

`engine/judge.js` `BANDS` — 계획서 '미니 확인 게임' 표(4분음표 판 기준). 연구값에서 유도한 **추정값**이라 2027년 3월 시범 기록으로 다시 맞춘다. 판정 창은 가장 짧은 음 간격의 35%를 넘지 않게 줄인다(`windows`).

| 너그러움(화면 이름) | 학년(선생님용) | 일찍(ok) | 늦게(okLate) | 딱(great) | 빠르기 |
|---|---|---|---|---|---|
| 넉넉하게 · `low` | 1~2학년 | 150ms | 180ms | 70ms | 100~120 BPM |
| 보통 · `mid` | 3~4학년 | 115ms | 115ms | 55ms | 80~130 BPM |
| 촘촘하게 · `high` | 5~6학년 | 100ms | 100ms | 45ms | 60~150 BPM |

지연 맞추기의 다시 재기 기준(120ms 밖 버림 · 5개 이상 · 흔들림 40ms 이하)도 같은 파일 `estimateLatency`에 있다 — 역시 시범 뒤 다시 본다.

`t = { o, sp, m, lat, band, bpm }` — `engine/judge.js` `tapStats`. 모두 반올림 정수(기록 크기).
- `o` = 맞힌 두드림 어긋남의 **가운데 값**(ms · 기기 지연을 뺀 뒤 · 앞당김은 음수). 맞힌 두드림이 없으면 null.
- `sp` = **퍼짐 = 사분위 범위**(Q3 − Q1 · 가운데 절반이 퍼진 폭 · 선형 보간). 표준편차보다 한두 번 크게 빗나간 두드림에 덜 흔들리고, 판정 창 '안'만 모은 값이라 꼬리가 잘려 있어도 뜻이 같다. 맞힌 두드림이 하나뿐이면 0 · 없으면 null.
- `m` = 놓친 박 수 · `lat` = 그때 뺀 기기 지연(`mn.latency.ms` · 없으면 0) · `band` = 판정 창 이름(`low` · `mid` · `high` · 악1은 늘 `low`) · `bpm` = 그 판 빠르기(악1처럼 악보마다 다르면 막대마다 빠르기의 가운데 값). 판정 창 폭은 `band` + `bpm`으로 `windows()`에서 다시 셀 수 있다(가장 짧은 간격의 35%로 줄어든 것까지).
- 같은 줄 `r` = 어디서 — `solo`(방 밖) · `room`(방에 든 기기 · 소리는 이 기기) · `tvs`(소리는 TV · 답만 이 기기). TV 소리 기록과 이어폰 기록을 가르는 꼬리표(예전 줄은 `r` 없음).
- 보는 곳: 선생님 칸 '이 기기 기록'(#/records) → 접힌 **'자세히'**를 열면 '두드림' 열(예: `+12ms · 퍼짐 40 · 놓침 1` · 칸에 마우스를 올리면 어디서 · 지연 보정 · 판정 창 · BPM). '모두 복사'에는 숫자가 칸마다 따로 들어간다(표 프로그램에서 셈).
- 자동 판정 보정은 하지 않는다 — 반 가운데 값에는 기기 지연과 사람의 앞당김이 섞여 있다(토론 L7 · 교사가 시범 2~3주 기록을 보고 정함).
