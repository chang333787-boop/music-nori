# 기준표 — '다 됐다'의 뜻 (11-14)

교사 말(11-14): "내 기준은 낮지 않다 · 내년 연구대회 1등급용 · **실제 사용을 빼고** 이 기준을 모두 100으로."
이 문서는 갈래마다 **100이 무엇인지**를 숫자로 정해 둔다. 지금 숫자는 손으로 적지 않고 `node tools/bar.mjs`가 장부에서 뽑는다(`--list` = 비어 있는 단계까지).

이 기준은 **우리가 정한 것**이다. 연구나 심사 기준에서 가져온 것이 아니다. '100'은 "장부에 적은 일을 다 했다"는 뜻이지 "아이에게 잘 통한다"는 뜻이 아니다 — 그것은 실제 사용에서만 알 수 있고, 이번 목표에서 뺐다.

| 갈래 | 100의 뜻 | 재는 곳 |
|---|---|---|
| 내용 범위 | 공부 흐름의 단계 62개마다 **아이가 하는 칸**(보기 → 연습 → 확인 게임)이 하나 이상 있다 | `engine/flow.js`의 `cell:` × `engine/cells.js`의 `first` |
| 5~6학년 쪽 | 난이도 4~5 단계 20개마다 칸이 있다 | 위 + `engine/load.js` |
| 요소 고르기 | 요소 열 개가 **모두** 제 단계를 다 채웠다(가장 낮은 요소의 %를 점수로 쓴다) | 위 |
| 활동 깊이 | ① 단계마다 **듣고 가려내기**와 **손으로 하기**(직접 내기 또는 악보에 넣고 빼기)가 둘 다 있다 ② 요소마다 **만들기**(정답 없이 제 것을 만들어 듣기)가 하나 이상 있다 | `engine/depth.js`(단계마다 L · D · E · M — 코드에서 확인한 것만) |
| 소리(기계로 잴 수 있는 것) | 음 높이 · 악기 사이 크기 · 세기 단계 · 작은 스피커 · 깨짐 · 때 · 칸이 묻는 차이 — 잰 항목이 모두 문턱 안 | `tests/ear.report.json`(`npm run test:ear`) · 문턱과 까닭 `docs/ear.md` |
| 화면 마감 · 자동 시험 | `npm test` · `test:browser` 모두 통과 · 만든 칸 모두 화면 규칙 검사(1366×768 · 스크롤 0 · 글자 18px↑) 통과 · 처음 보는 눈 평가에서 '진짜'로 남은 것 0 | 시험 · `docs/eyes.md` |
| 실제 사용 | (이번 목표에서 뺌) 실제 크롬북 · 아이 · 교실에서 써 본 기록 | — |

## 활동 종류 넷
- **L 듣고 가려내기** — 소리를 듣고 단추로 고른다.
- **D 직접 내기** — 박을 치거나 건반 · 단추를 눌러 때 · 높이를 맞춰 소리를 낸다.
- **E 넣고 빼기** — 악보에 기호 · 음표를 넣거나 빼고 달라진 소리를 듣는다(칸 안의 채우기 · 악보 판).
- **M 만들기** — 정답 없이 제 리듬 · 가락 · 짜임을 만들어 듣는다.

## 100이어도 남는 것 (숨기지 않는다)
- **사람 귀** — 기계는 숫자만 잰다. 합성음이 아이 귀에 그 악기처럼 들리는지, 작은 차이가 들리는지는 사람이 들어야 안다. 선생님이 한 번에 들어 볼 수 있게 점검 쪽을 둔다.
- **진짜 소리** — 목소리 · 물체 · 타악기 · 국악기는 녹음이 없고 모두 컴퓨터로 만든 소리다. 녹음 파일을 내려받는 일은 선생님 허락이 있어야 한다.
- **난이도 · 차례** — `engine/load.js`는 앱이 스스로 따진 것이다. 아이 자료로 확인한 것이 아니다.
- **교과서 대조** — 2022 개정 교과서와 맞춰 보지 못했다(`docs/flow.md`).
